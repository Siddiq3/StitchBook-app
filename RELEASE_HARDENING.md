# Android release verification

The committed Android/iOS folders are the native configuration source of truth. Only Expo Doctor's known `appConfigFieldsNotSyncedCheck` is disabled for this intentional workflow. All other Doctor and compatibility checks remain in CI.

Unsigned native verification is supported. A signed release requires all four external variables: `UPLOAD_STORE_FILE`, `UPLOAD_STORE_PASSWORD`, `UPLOAD_KEY_ALIAS`, `UPLOAD_KEY_PASSWORD`. Partial credentials, the debug keystore/alias, and missing or non-HTTPS `EXPO_PUBLIC_API_BASE_URL` fail release configuration validation. Keep keystores outside Git and supply them through secure CI/host configuration. See [Android app signing](https://developer.android.com/studio/publish/app-signing).

Local verification built `android/app/build/outputs/bundle/release/app-release.aab` with Gradle's arm64 release variant using cached dependencies. `jarsigner -verify` explicitly reported it unsigned. This is evidence of native compilation, not a signed publishing artifact. The merged release manifest has Internet, vibration and dependency-owned receiver/install-referrer permissions. It has no camera, microphone, broad storage, overlay, biometric or fingerprint permission. Current source has no camera/photo-picker calls; re-audit permissions if those features are added. Backup and cleartext traffic are disabled in release; development exceptions remain in debug configuration.

Before publishing, complete approved npm installs/lockfile regeneration, `npm ci`, tests, the online Expo compatibility/Doctor checks, security audits, and a signed build in the protected publishing environment. Validate the installed signed app on a physical device, including Google OAuth using upload and Play signing fingerprints, network loss, deletion re-authentication, cached data cleanup, customer/order/measurement workflows and Cashfree website checkout and entitlement refresh. The native Google SDK is signed out before deletion proof is requested to avoid cached old identity tokens. iOS and authenticated end-to-end flows were not verified here.

The current native toolchain targets SDK 35. Check current Play Console target/API, alternative billing, privacy/Data Safety, account-deletion and developer-verification requirements before publication; repository compilation cannot prove store-policy approval. Configure real app store/download links on the website. Owner-approved legal terms and accurate hosted privacy/deletion disclosures are still required.

Dependency work is pending npm network approval. Intended overrides in `package.json` are not installed or reflected in the lockfile yet. Do not publish or treat CI as green until that work is complete. Metro's image-size dependency needs a compatible security fix; its API cannot safely be replaced with a new major version solely to silence audit.
